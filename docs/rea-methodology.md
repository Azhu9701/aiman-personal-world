# REA：以证据核对本地读取行为

这里记录的是一种通用的分析与验证方法：把观察、推断、实现和验证分开。它不是运行时取钥教程，也不包含应用签名、系统保护修改、进程附加、私人应用指纹或用户账号信息。

## 从可观察事实开始

先明确用户授权的数据范围、要实现的只读目标，以及最终如何检查结果。记录输入类型、公开格式说明、源码适配位置和测试条件。不要因为某个目录存在，就断言其中所有数据可读或全部历史已保存。

静态材料可以说明代码路径、数据库名称、加密接口和格式处理；但不能单凭字符串或函数名证明运行时一定这样调用。运行时观察也只适用于已观察的条件，不自动推广到其他版本或设备。

## 建立可反驳的解释

提出最小假设，例如“一个消息分片有多张会话表”“某个发送者整数通过名称映射表解析”“正文可能压缩”“媒体原文件与数据库资源记录分离”。每条假设都对应一个可读的字段、结构或合成测试。

优先读取公开上游源码与官方格式文档，并保留出处和许可证。涉及真实数据时只在已授权范围内处理；公开仓库使用人工结构和计数示例，不能把私人观察记录作为样本上传。

## 实现保持可审计

把原始数据作为只读来源。处理 SQLite 类存储时，明确 WAL 的作用、复制一致性与完整性检查；不能丢弃日志后假称快照一致。对无法读取的数据库、表、压缩内容或媒体，产生明确状态，不返回伪空成功。

输出保留稳定消息身份、来源统计和解析状态。正文解析提取人类可读内容，避免把密钥、下载令牌或原始敏感 XML 传播到浏览器。未知发送者和未知会话保留记录并标注不确定性。

## 验证解释，而不只验证程序能运行

合成测试应覆盖正常与反例：多分片重复行号、同秒排序、WAL 中尚未合并的消息、错误密钥、缺少必要表、压缩或 XML 异常、同名不同会话、已交付与线下推进语境。

来源行数、归档行数、索引行数必须分别可核对。媒体“有路径”“文件存在”“格式可解码”“浏览器可打开”也是不同检查；任何单层成功都不能包装成完整内容恢复。
