# 日程与行程 · v0.4.0 预览

从工作台左侧「日程与行程」进入 `/agenda`。它把本机聊天中的约定整理为待确认线索，人工补全后进入本机行程，而不是自动把聊天发给日历服务或把邀请当作已接受。

## 三个阶段

**发现线索**：默认显示本人及私聊对方的候选，群聊可另行查看。日期词与见面、会议、出行、聚餐、就诊、截止等词共同命中才进入待核对列表。本人/对方/群聊/未知方向均保留区别；命中不证明本人参加、活动真实或约定仍有效。

**核对并安排**：看原话与上下文，检查可能取消/改期的后续消息，填写自己的日程标题、明确起止时间与时区，地点未知可以留空。结束时间没有默认值。确认「本人参加且仍有效」与日历覆盖范围后，先检查冲突，再决定加入本机行程。

**查看与导出**：已确认安排按时间排列，显示本人填写的准备/交通/休息预留。导出必须逐项选择；只输出标题、时间、地点，不含聊天正文或联系人。可以明确勾选同时导出预留时间。下载的是 `.ics` 文件，不是 Google/Apple 实时同步；没有邀请、订票、导航查询或自动提醒。

## 日期如何解释

来源日期按消息发送时间和 `Asia/Shanghai` 解释，与扫描当天无关。支持数字完整年月日、月日、今天/明天/后天/大后天、明确星期，以及24小时钟点、中文上午/下午钟点和同日明确起止区间。跨年省略年份、裸星期会提示假设；不能确知的异地时区、多个日期或选择性钟点、不清楚的上下午、跨日结束、周期安排等进入待补全，不自行挑选。

本版不是通用语义解析器：不会完整理解多轮邀约，不会把「好的」自动并到某项会议，不覆盖所有口语日期，也没有实体身份消歧。日期和地点提示可能错误，最终字段由本人确认。时间保存使用明确IANA时区；夏令时不存在或歧义钟点拒绝保存，不暗中选择一个偏移。

## 有效性和证据

默认扫描最近90天、最多50,000条主来源文本；明确排除其他来源 `pw:` 命名空间和未来发送时间。结果最多返回200条，公开覆盖数量与截断情况。已解析且过期的约定从候选中略过，但统计数量；这不是对全部聊天或全部未来行程的完整检索。

后续同会话中出现取消、改期或延期措辞时，展示「可能变化」，不因同一会话就认定是同一约定。后续检查上限为原日期/消息后30天附近，最多展示12个变化证据链接；指纹覆盖纳入检查的全部变化消息。取消措辞不能直接确认入日程；改期和可能变化须本人回看。电话、其他会话和线下变化可能未记录，不能保证有效性。

每个确认日程存来源消息编号及指纹，不复制原聊天。原消息更改、相关后续变化、来源读取范围不再包含它时，暂停导出并要求复核；人工安排仍保留。每条来源只保存一个对应日程，更新不追加重复记录。确认、取消、忽略和导入快照均有全局revision并发检查；与归档合并共用StateLock。

## 冲突检查及局限

检查确认的本机日程和手动导入的外部忙碌快照，包含本人填写的前后预留时间。冲突会阻止保存和导出。建议时间仅在未来7天、每日09:00–18:00中检索不重叠时段，是重新约时间的参考，不会移动已确认安排，也不保证其他人有空。

外部快照只保存覆盖起止、读取时间、来源标签和忙碌区间，不含日历标题、联系人或OAuth令牌。超过一小时显示过期。零忙碌只表示这个来源在该覆盖区间没有busy记录，不能代表其他日历、透明事件或线下安排。软件不主动刷新快照，也不因ChatGPT可访问Google Calendar就自动取得长期权限。

准备/交通时长必须本人填写，默认0明确表示未预留；不使用地图，不判断实际路线或是否能赶到。不虚构出发地、交通工具和航班。全天事项采用不包含在内的结束日期，不自动把模糊的「下午」变成全天事项。

## 日历文件边界

按RFC5545生成CRLF和UTF-8按字节折行的日历内容，文本转义防止插入其他日历属性。时刻使用UTC，全天采用日期。UID随机生成并在本机同一日程修订中保持稳定，SEQUENCE递增；不含来源消息ID。没有ATTENDEE、METHOD:REQUEST或VALARM。

文件导出不等于已导入日历。同一文件重复导入是否去重、修订是否更新由接收软件决定。取消本机安排不发送外部取消，也不会删除已导出的副本；需要本人到外部日历处理。参考：https://www.rfc-editor.org/rfc/rfc5545.html

## 存储与隐私

`agenda-state.json` 是单独的本机私人文件（0600），保存本人确认内容、来源引用、被忽略编号以及主动导入的busy快照。读取候选不创建它。没有云模型调用、自动共享或应用级静态加密；不改变原始归档、索引、画像或旧草稿。真实聊天、日程或busy快照均不得放进公开仓库，发布检查会阻止该文件被提交。

## 接口和验证

- `GET /api/agenda`：候选、日期解释、状态、覆盖、已确认行程、冲突和快照范围。
- `POST /api/agenda/preview`：补全字段后的冲突预览，不写文件。
- `POST /api/agenda/update`：confirm / cancel / dismiss / busy_snapshot；每次带expected_revision。确认须有reviewed=true与ack_scope=true，并在有来源时提供source_id和source_fingerprint。
- `POST /api/agenda/export`：明确的ids、expected_revision、ack_scope及可选include_buffers。只返回ICS文本，不自动写日历。

所有接口继承本机Cookie及同源限制。单独临时状态中的手写反例在 `test_agenda.py`，包含相对日期、过期、未知关系、取消改期、冲突、并发、来源变化、DST、导出注入和无网络边界。真实Chromium测试 `scripts/test_agenda_browser.mjs` 仅加载手写数据，使用固定测试时钟，不访问真实聊天或个人浏览器会话。

本轮真实聊天日程扫描的工具请求被安全检查阻止，未绕过。不能把合成测试结果称为真实行程已经提取或安排完成。
