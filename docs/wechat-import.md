# 可选：导入兼容的微信本地数据

普通用户应先运行 [人工演示](getting-started.md)，或者导入已有规范归档。下述路径面向**已经合法持有本人数据及可用 SQLCipher 密钥**的用户；它不是获取密钥的入口。

本发行包没有取钥、重签微信、创建调试副本、附加进程或改变 SIP/系统保护的工具，不会替你完成这些操作。密钥缺失或不匹配时，程序应报出相应状态并保留既有结果，不能把加密数据库显示成空聊天。

## 兼容范围

适配器面向已经实现和检查过的微信 4.x 风格本地数据布局：联系人、会话、消息分片，以及部分资源、媒体、头像与本地聊天机器人记录。目录布局和表结构仍由实际数据决定；本项目不承诺所有客户端版本或全部消息类型兼容。当前微信 `refresh` 在 Windows 明确不支持；Windows 仍可使用标准库演示、规范归档导入与浏览。

文本主导入选择 `contact/contact.db`、`session/session.db` 和匹配 `message_N.db` / `biz_message_N.db` 的消息分片，遍历其中每张受支持的会话消息表。未知会话名称保留稳定标识。记录层完整性只针对这个声明的来源范围。

## 可选依赖

| 能力 | 依赖与条件 |
|---|---|
| SQLCipher 数据库 | `sqlcipher3` 或兼容 Python 绑定，或可用的 SQLCipher 原生库；必须支持加密与 HMAC 检查 |
| 压缩正文 | `zstandard`；缺少时保留压缩正文无法解码的状态 |
| DAT 图片解码、格式核验 | `Pillow`、`cryptography`，以及兼容的现存本地缓存 |
| Silk 语音转 WAV | `pilk`；在本机解码为 24 kHz 单声道 WAV，不进行语音识别 |
| 部分 HEVC 图片首帧、AMR 音频或视频验证 | 独立安装的 FFmpeg / FFprobe；仅处理本地文件 |

依赖声明见 `requirements-wechat.txt`。平台上某些 SQLCipher 或音频包需要编译器和原生库，不能保证一次 `pip install` 在所有系统成功。先运行 `doctor` 查看可用项；项目不会自动安装依赖、模型或提升权限。分开的图片解释器必须也具有所需图片依赖。

## 配置并手动刷新

下面都是需要替换的占位路径，不包含任何密钥值：

```bash
python3 personal_world.py configure --db-root "/path/to/db_storage" --key-file "/path/to/private-keys.json"
python3 personal_world.py doctor
python3 personal_world.py refresh --no-open
python3 personal_world.py verify
python3 personal_world.py open
```

可通过 `--python` 指定已有 SQLCipher 支持的解释器，通过 `--sqlcipher-library` 指定本机 SQLCipher 动态库，通过 `--image-python` 指定图片解释器，通过 `--ffmpeg` 指定本机 FFmpeg。`--app-data` 可显式指定兼容的本地应用数据位置，`--source-version` 保存用户填写的来源版本说明。使用 `--state` 选择私人工作空间。不同环境可用选项以 `python3 personal_world.py configure --help` 为准。

`--self-id` 只接受已经核实的本人内部用户名。不要根据文件夹名猜测或随意删后缀；未确认时保留未知方向。配置只引用本机密钥文件，不把密钥值写进命令行。

在 POSIX 系统上，密钥与私有配置应为本人所有且仅本人读写的普通文件（`0600`）。程序不会为了成功读取而自动扩大文件权限或尝试其他账号。

## 已有密钥文件的形态

密钥文件是本机 JSON 对象。建议以数据库相对于 `db_storage` 的路径为键，每项值为十六进制 raw key，或者含 `key` / `enc_key` / `raw_key` 字段的对象。也兼容外层 `keys` 对象、盐值映射 `salt_keys`、以及受支持 schema 版本中的盐值索引形式。

每个加密数据库的 key 必须是 64 或 96 位十六进制：64 位对应 32 字节原始密钥；96 位形式额外包含 16 字节数据库盐。后者的盐必须与该文件头匹配。默认按 SQLCipher 4 兼容参数打开，保留 HMAC 验证。这里不提供可运行的假密钥配置，避免被误当成成功初始化。

代码也兼容 basename、绝对路径和默认 key 形式，但多分片来源更适合逐库相对路径，减少错误复用。**捕获一个 key 或打开一个库，不是全库成功。** 所选消息、联系人与会话库都要通过读取和完整性检查；媒体辅助库的可用情况另外报告。

## 刷新与失败边界

刷新建立新的一致性副本，复制选定数据库及 WAL，在读取副本时验证数据库，再构建新归档、补充支持的本地子系统和媒体、建立索引并核对。它不使用 SQLite 直接打开微信原库，也不会写入微信数据库。

源文件持续变化、必要密钥缺失、必要数据库验证失败、未知的强制字段或数量不一致，会阻止发布新的完整结果。媒体辅助文件缺少或格式不支持可产生明确占位与分类统计；它不应抹掉已导入消息或伪称媒体完整。

刷新是用户手动执行的完整导入，不是后台增量同步。`refresh --timeout` 设置每一步时限，默认 7,200 秒。大型来源需要足够本机空间保存副本、归档、索引和媒体；具体覆盖以本次清单与验证为准，不以宣传中的记录数量为准。

## 已有媒体能恢复到哪一步

媒体增强优先通过数据库中的消息身份、资源记录、摘要、文件大小和已有缓存位置精确映射文件，验证后复制到私有媒体缓存。输出引用使用内容摘要命名，不暴露原媒体目录。消息 ID 在增强前后必须一致。

图片可能恢复为完整可读图、已有缩略图或仅首帧；它们有不同状态。可用的本地视频提供浏览器播放路径；文件保持字节内容供下载；支持的语音在本机转 WAV，不安装识别模型、不生成 ASR 文本。语音可播放不等于正文可检索，图片也没有 OCR。

本地表情有独立缓存与加密格式。当前版本**尚未完成该表情格式解码**，即使资源摘要能对应某个本地文件，也不能直接称为可打开表情。它保留 `sticker_mapping_unavailable` 一类明确状态。未下载、已清理、无法精确匹配或暂不支持的附件也保留说明，不能混同为“微信中从未存在”。

本版不从网络下载图片、视频、文件或表情，不上传媒体，不使用云处理，也没有自动发送功能。支持的格式和依赖范围以 [enrich_media.py](../enrich_media.py) 与实际分类结果为准。

## 许可与问题报告

DAT 处理部分参考并适配了公开媒体工具的少量代码，保留其 [第三方声明](../THIRD-PARTY-NOTICES.txt)。Pilk、Pillow、SQLCipher、FFmpeg 等独立依赖有各自许可；源码发行不附带运行时 vendor、模型、微信客户端或用户数据。

兼容性问题请用人工表结构或人工最小记录复现，不提交真实密钥、原库、缓存或聊天。报告已检查的平台、依赖可用状态和错误类别即可。
