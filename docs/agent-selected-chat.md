# Agent 读取所选私聊 · 插件0.5.0

## 实际能力与范围

0.4.0只有服务状态和导航工具。0.5.0增加四个真正返回消息资料的原生Harness工具：选区信息、原话搜索、消息上下文、按时间读取。Agent可以据此整理需求、追溯约定变化、提出跟进草稿并引用消息证据，而不是只给页面链接。

**本版处理的是本人明确导出、预览并授权上传到本机插件内存的会话范围，不是直接读取整个微信库。** 原始索引桥接的工具调用被安全检查阻止后，没有改用隐藏通道或另一个模型绕过。本版改为更窄的、用户介入的数据边界。

插件版本0.5.0，兼容性锁定实际验证的DeepSeek Harness 0.2.0-rc.2。打包的独立Python工作台核心仍是0.4.0，没有修改原归档或其数据库结构。

## 本人操作

1. 从Personal World微信历史打开目标会话，选择“导出JSON”。
2. 从Harness的“个人世界”入口点击“选择聊天交给Agent”，选择刚才的单会话JSON文件。
3. 设置开始/结束日期和最近消息上限，检查预览。文件先只在浏览器内解析；此时没有上传到插件或模型。
4. 勾选用途与模型披露确认，点击“建立分析选区”。只有选中范围进入当前Harness进程内存，模型尚未被调用。
5. 复制生成的任务到Harness对话。Agent使用选区ID调用工具；每次取数都向Harness原生approval服务请求本次授权。

在同一页面可以查看当前浏览器建立的选区，并撤销。没有自动从文件系统找微信、没有自动导出所有联系人、没有默认全库开放。不会后台刷新文件；需要更多历史时由本人建立新的明确选区。

## 四个实际消息工具

`personal_world_selection_info(selection_id)` 返回所选会话、消息数量、实际时间范围、有效期和剩余额度。

`personal_world_search_messages(selection_id, q, offset?, limit?)` 在所选消息中做字面子串匹配，返回原文片段、消息编号、发言方向、时间、文本截断标记及下一页位置。不宣称语义检索。

`personal_world_message_context(selection_id, message_id, before?, after?, text_offset?)` 查看同一选区和会话中前后最多各4条消息，并支持读取长消息的下一段。范围之外的中间消息或后续变更可能缺失，`complete_context`始终为false。

`personal_world_timeline(selection_id, offset?, limit?)` 按原消息时间读取选中消息，每页最多20条。返回UTC时间戳并标明源时间解释为Asia/Shanghai；“明天”等词应按消息时间理解，不以查询今天替代。

原有 `personal_world_status`、`personal_world_navigation`继续不返回私人消息。没有模型可调用的导入、发送、写外部日历或确认约定工具。Agent生成的判断和跟进文本只在当前对话中形成；要保存为正式画像、日程或发给别人，仍需另行明确操作。

## 权限与披露

每次消息读取的工具体内直接调用Harness原生`approval.request`，不是模型自己填一个`approved:true`字段。只有`allowed-once`可以继续。无Agent上下文、原生审批服务缺失、审批异常、拒绝、取消、待审批期间失效/撤销均不能返回消息。首次获准读取后，选区绑定到该Agent的身份；另一个Agent不能复用它。

授权服务按宿主现有配置选择人工或其他审核插件回答。本插件不会修改或替换该回答链，也不把自动审核结果伪称为用户点击。上传前的明确范围及模型披露确认是另一道用户动作；模型没有建立选区的工具。

**被Agent实际读取的文字可能送给当前模型服务商，并留在Harness会话日志中。** 本地保存原始文件不等于模型计算也完全在本地。撤销选区或重启Harness只能停止后续取数，不能删除已返回的上下文、会话日志或服务商可能保留的副本。

## 限额与存储

浏览器选取文件最大32 MiB；提交选区最多500条、2 MiB。一个进程最多10个选区；每个选区一小时到期。单次返回最多20条、48 KiB，每条首次最多1200字符；单选区累计披露上限256 KiB。达到上限不会暗中扩大，需要本人重新检查范围。

选区保存在插件内存，不写入原归档或额外明文副本文件；重启、到期清理或本人撤销后不可继续查询。内存回收不等于可靠擦除，原导出文件仍由用户自行保管，实际工具结果也会随Harness正常会话持久化。

上传规范化仅保留所需的会话ID/名称/群聊标记，以及消息ID、会话ID、发言名、方向、时间、类型和文字；丢弃头像、媒体URL、额外路径及来源配置等未使用字段。附件和语音内容不会自动解码或送给模型。单会话归属、唯一消息编号、时间/体积/条数均有校验。

## 信任与防误判

所有消息视为资料而非指令。JSON原文即使包含`<system>`、外部发送要求或命令，也不能改变系统政策。输出保留来源ID、时间、上下文不完整标记、哈希和本机回链；哈希仅表明所选数据的一致性，不证明导出文件真实或来自官方服务器。

邀请不等于已接受；取消/改期要回看原话，未写结束时间不补造时长。不对他人做人品或可信度评分，不根据有限选区编造完整个人历史。

本插件不是隔离同一OS用户下其他任意代码的安全沙箱。它的模型工具没有任意路径、SQL、终端、网络发送能力；Harness中其他已安装工具的权限由宿主管理。本机上传页面通过loopback/Host/同源、私有Cookie和明确确认限制外部网页访问，不提供向外网公开个人资料的接口。

## 验证方式

单元测试覆盖真实文字返回、逐次授权、拒绝/取消/异常、选区归属、跨Agent复用拒绝、长文分页、额度、过期/撤销、同源上传及恶意文字的字面处理。

`scripts/test_agent_selection_browser.mjs`只选择代码生成的4条人工消息，使用单独测试profile和临时浏览器。可明确启用一次真实模型冒烟测试，检查“选文件→预览→范围授权→原生工具授权→取原话→识别后续取消→证据结论”的链路。测试授权仅针对这个人工选区，不代表已替用户授权任何真实私聊。

## 本轮实际验证结果

19项原生工具形状/选区/权限/HTTP单元测试通过。浏览器先选择4条手写人工消息并明确提交，尚未调用模型时验证了选区没有绑定Agent。随后通过当前已配置模型在真实Harness新建测试会话中完成：4次仅本次授权、实际返回消息内容、搜索机械臂需求、读取后续取消消息、输出含消息编号的分析。测试选区随后撤销。

这些是人工样本端到端验证，不代表已经分析了用户真实私聊。本轮没有读取或上传真实微信内容，也没有修改已有归档、索引、画像或日程。早期一次测试没有取得消息返回，最终一次实际完成上述链路；没有把未返回消息的运行计为成功。
