# AIMAN Personal World

**把自己的本地聊天变成可浏览、可回看证据、可人工复核的个人工作空间。**

v0.3.0 是一个可运行的早期版本：导入规范聊天归档，浏览历史，用本地关键词与规则寻找机器人、机械臂、供应和控制方案等主题中的需求、供给、合作线索；从每个候选回到原始消息，再由你决定是否跟进或起草文字。新增个人画像页，可从本人文本中核对自述、维护介绍并预览分享。

它目前不调用大模型，不做语义搜索，不判断某个机会确实没有推进，也不评价一个人是否可信。公开的 AIMAN Robotics / Manufacturing 世界连接属于后续计划。

## 先运行人工演示

只需要 **Python 3.10 或更高版本**。演示与规范归档查看使用 Python 标准库，不需要微信、数据库密钥、模型、云账号或媒体依赖。

1. 下载本仓库源码并解压，在源码目录打开终端。
2. 检查 Python 版本，然后运行演示：

   ```bash
   python3 --version
   python3 personal_world.py demo
   ```

   Windows 如使用 Python Launcher，可将 `python3` 换成 `py -3`。

3. 浏览器会打开本机地址，默认端口为 `18792`。页面持续显示人工示例标识。

演示包含 **8 个虚构会话、40 条人工消息，时间跨 2023—2026 年**。名字、需求、产能、事件和时间均为虚构。演示使用独立的数据目录，不会搜索你的微信账号或覆盖已有个人归档。[查看示例数据](examples/demo.json)

在无桌面或脚本环境中，只准备演示数据、不启动服务与浏览器时，可以使用：

```bash
python3 personal_world.py demo --no-open
```

需要重新打开演示时，可再次运行 `python3 personal_world.py demo`。请使用 CLI 打开的已连接页面；仅手动输入本机地址不会建立访问凭据。服务启动、诊断和端口选项见 [运行与导入](docs/getting-started.md)。

## 在界面里可以做什么

| 工作区 | 当前作用 | 怎样核实 |
|---|---|---|
| 行动工作台 | 查看导入概览，并按本地规则整理需求、供给、合作候选 | 核对人工示例标识、覆盖范围和消息 ID；规则分数只用于排序 |
| 微信历史 | 浏览、搜索、分页和导出已导入会话 | 回看原消息及已恢复的本地附件 |
| 时间线 | 按时间浏览和筛选聊天证据 | 回到原会话，检查同一话题的前后文 |
| 关系图 | 展示会话、主题和会话范围内发送者的关联 | 每条关联带消息证据；同名不自动合并为同一人 |

已有聊天浏览、搜索、分页、附件访问和单会话导出仍可使用。已保存且兼容的图片、视频、语音、文件与头像可以接入；没有本地素材或尚未解码的内容保留状态，不伪装成完整附件。

你可以把候选标记为待核查、跟进、忽略或已完成，也可以生成一份本地模板草稿。**标记是你的工作记录，草稿尚未发送。** 本版本没有向微信联系人或其他第三方发送消息的功能。

## 导入自己的数据

已有符合格式的 JSON 或 JSONL 归档时：

```bash
python3 personal_world.py import "/path/to/your-export.jsonl"
python3 personal_world.py verify
python3 personal_world.py open
```

导入器会建立独立索引。原归档中的稳定消息 ID 是证据回溯的基础。不要把不同会话中相同的本地行号当作全局唯一 ID。格式、示例及完整性要求见 [数据格式](docs/data-format.md)。

本项目也提供可选的微信本地数据库适配器。它的前提是：你已合法持有本人数据及可用的逐库 SQLCipher 密钥。发行包**不包含取钥、重签名、调试微信或关闭系统保护的工具**，也不会自动执行这些操作。配置、依赖与兼容边界见 [微信导入](docs/wechat-import.md)。

## 数据与判断如何留在本地

原始归档与导入索引是消息证据来源；规则候选和关系图是可重新计算的视图。`workspace.sqlite` 保存人工复核与草稿等派生工作状态，不是新的事实来源。

默认服务只监听 `127.0.0.1`，浏览器通过本机会话令牌访问数据 API。个人归档、索引、媒体、人工标记和草稿都留在本机；当前没有遥测、云端推理、自动外站检索或消息发送。[隐私设计](docs/privacy.md)

**本版本尚未提供应用级静态加密。** 在 macOS/Linux 等 POSIX 系统上，私人数据目录使用 `0700`、私有文件使用 `0600`；Windows 尚无应用内 ACL 自检。这些权限不能替代磁盘加密。归档、媒体缓存、工作状态和备份都可能包含可直接读取的私人信息。可以按自己的环境启用 FileVault、BitLocker 或其他操作系统磁盘加密，本项目不会替你启用，也不判断它们当前是否开启。

## 如何理解候选结果

一条“机械臂 + 需要”命中，只证明该消息包含了这些词语。它可能是旧需求、引用、公告、否定句或已经完成的事情。没有命中后续消息，也只表示**在当前导入范围和当前规则中没有找到匹配**，不证明现实中没有推进。

因此，每个候选保留消息证据、命中信号、时间范围和待核实事项；规则分数是检索排序，不是成功概率、人的信用分或商业事实。跨会话需求/供给线索只表示共享具体主题，未核实兼容性和当前状态。最终判断需要你检查原文及现实情况。[方法与不确定性](WORLD.md)

语音可播放不代表其内容可检索：当前没有 ASR、图片 OCR 或表情格式完整解码。规则主要使用中文词表与少量英文别名，不是通用语言理解。

## 开发与发布检查

```bash
python3 -B -m unittest discover -v
python3 -B scripts/release_check.py
```

测试使用人工数据。需要 Pillow、cryptography 等可选模块的媒体测试会在依赖缺失时明确跳过；跳过不代表这些路径已经验证。CI 配置在 Ubuntu 和 macOS 运行标准库测试及发布检查，并通过 Node 运行 `scripts/test_frontend.mjs`。后者是 DOM 交互与本地 API 集成检查，不是浏览器视觉、布局或原生媒体播放审计。

发布检查针对可发布文件集合检查运行时数据、密钥或配置、数据库、非人工 JSON、私人固定路径及可疑秘密值；它不能证明一段普通文字绝无隐私，公开前仍需要人工审查。[贡献指南](CONTRIBUTING.md)

## v0.1.1 · 把日常使用闭环补齐

草稿窗口现在可以编辑标题和正文，再点击“保存修改”。重开页面后继续编辑；版本记录保留原始生成稿与各次已保存内容。多个窗口同时修改时，旧窗口不会静默覆盖新版本；冲突后可以先复制自己的文字，再读取最新版本合并。页面退出时会对未保存编辑提示，尚未提供自动保存。

完成或排除的讨论会从其他候选的关联线索和新生成草稿中隐藏；这只是人工工作筛选，不改变原消息和证据指纹。依据变化的旧记录会回到待核实列表，保留原标记与备注；它不会自动恢复成可推荐的合作方，需要本人重新复核。“我的复核记录”也会显示当前无法定位来源的旧记录。

这些改进仍不包含语义模型、持续后台同步、发消息或应用级静态加密。旧草稿引用的来源或关联状态改变后，可以查阅和复制，但必须核对当前线索并生成新稿，不能把旧稿直接保存成基于新证据的决定。

开发者可使用已安装的 Node 与 Chromium 运行 `scripts/test_browser.mjs`。该检查只读取手写演示数据，创建独立临时浏览器配置，不连接本人的浏览器登录态，也不下载浏览器。细节见 [架构](docs/architecture.md)。

## v0.2.0 · 分批补历史，安全累积更新

页面“数据来源与导入”新增 **补充历史 / 查看导入批次**。选择本机规范 JSON/JSONL 文件，先核对新增、重复和冲突数量，再确认合并。不同来源可以显式分开，旧文件不会默认覆盖新内容，短快照也不会清空已有长历史。

已配置的微信刷新现在也会合并到现有历史。新增消息及变化文字才写入对应索引；取数仍是完整快照校验，没有常驻后台采集。原有备注和草稿不随归档替换，来源变化仍会提示复核。

可以查看按月覆盖、导入批次和保留的规范来源快照。未导入的更早年份不会被声称已恢复；在原微信删除内容不会自动删除此处的档案。本版本增加强制中断后的发布恢复检查，仍未实现应用级静态加密或历史删除界面。

完整用法、空间开销和边界见 [历史导入与增量更新](docs/history-import.md)。

## v0.3.0 · 个人画像

从左侧“个人画像”进入：查看本人文本中的关注话题与月份变化，核对第一人称原句，按“指令 / 身份 / 职业 / 项目 / 偏好”确认或修订自己的介绍。支持暂不采用、停用某个会话、删除条目，以及只对明确选中的有效确认条目生成分享预览。

画像由本人维护，不是性格诊断或对其他人的评价；只读主来源标成本人发送的文本，不调用模型。资料未上传云端，但没有应用级静态加密。过滤不等于完美脱敏，分享前仍需检查；删除仅影响本功能的记录，不会删除原始聊天与外部副本。详见[画像功能与边界](docs/personal-profile.md)。
